# 數位教具開發實務｜第 18 週
# 總結性 ENA–TPACK 歷程分析與期末焦點訪談
## 從「我做出了什麼」回到「我的設計判斷如何改變，以及哪些證據支持這個改變」

**授課時間：**120 分鐘  
**前置成果：**W17 Prototype vFinal、Final Evidence Story、W16 歷程反思、W15 AI–Human Design Profile、W1–W17 evidence archive  
**本週核心：**T2 → Evidence Completion → ENA/Connection Interpretation → Focus Interview → Multi-source Reflection  
**課程定位：**W18 是課程與研究資料的總結週，不再增加新作品功能，也不把任何單一分數或網絡圖當成學生能力的最終結論。  
**最低成果：**完成 T2（若研究設計採用）、個人歷程摘要、ENA／Connection interpretation、期末焦點訪談與資料完整性確認。

> 本週不是「公布誰的 TPACK 最高」。  
> 要回答的是：**在整學期的設計任務中，我留下了哪些證據，顯示自己如何把內容、學習者、媒介、AI 與實際測試逐漸連結起來？哪些改變可以被資料支持，哪些仍需保留不確定性？**

# Part A｜教師教案

## 一、W18 的三個任務

W18 同時完成三件事：

### 1. 課程收束
學生回看 W1–W17 的設計歷程，不再只看期末成品。

### 2. 個人學習反思
學生用 Evidence ID 說明自己的 turning points、知識連結與 AI–human judgment 變化。

### 3. 研究資料完成
完成 T2、自陳資料、evidence archive、焦點訪談與正式 ENA 所需的資料清理。

---

## 二、W18 與 W9／W16 的關係

| 週次 | 角色 | 主要問題 |
|---|---|---|
| W9 | 期中診斷 | 我目前留下了哪些 evidence？下一階段需要什麼 scaffold？ |
| W16 | 形成性歷程解讀 | 我的 evidence 中開始出現哪些 knowledge connections？ |
| W18 | 總結性整合 | 整學期的 evidence、T2、ENA 與訪談共同支持哪些歷程解讀？ |

W18 不應只是把 W9 或 W16 再做一次，而是加入**跨時間比較與多來源資料整合**。

---

## 三、本週學習目標

學生完成 W18 後應能：

1. 完成研究既定的 T2 TPACK 自陳量表，而不把量表分數等同實際設計能力。
2. 以 W1–W17 Evidence ID 回顧至少三個重要設計轉折。
3. 區分作品表現、事件資料、自陳量表、研究者 coding 與 ENA 的不同意義。
4. 正確解讀 ENA 的 code co-occurrence，不做能力排名。
5. 比較早期與後期 design episodes 中知識連結的變化。
6. 說明 AI 使用從「取得答案／生成內容」到「提出方案、驗證與人類判斷」的變化。
7. 在焦點訪談中以具體 evidence 回答，而非事後重構理想化故事。
8. 指出至少一項有資料支持的改變，以及一項仍無法確定的問題。

# Part I｜期末焦點訪談：核心問題

## 訪談原則
- 優先追問具體事件，不問抽象「你有沒有成長」。
- 要求引用作品、Evidence ID 或真實設計 episode。
- 不誘導學生說「AI 很有幫助」或「TPACK 有提升」。
- 允許學生回答「沒有改變」「不確定」。
- 訪談者不告訴學生研究者對他的 coding 判斷。

## 核心問題

### Q1｜最重要的設計轉折
「整學期哪一次證據最明顯改變你的設計？原本怎麼想？後來怎麼改？」

追問：
- 你還記得是哪一週／哪個作品嗎？
- 哪個 evidence 讓你改？
- 如果沒有那個 evidence，你可能會怎麼做？

### Q2｜技術選擇
「有沒有一次你最後決定『不要使用某個技術』？為什麼？」

追問：
- 是因為做不到，還是判斷不需要？
- 有比較其他媒介嗎？

### Q3｜Web AR 必要性
「現在回頭看，你認為什麼情況下 Web AR 才真的值得使用？」

追問：
- 如果 QR／紙卡也能做到呢？
- AR 帶來了什麼 friction？

### Q4｜AI–Human Judgment
「有沒有一次 AI 給的建議看起來很好，但你最後沒有照用？」

追問：
- 你依據什麼修改／拒絕？
- 哪個判斷你認為不能交給 AI？

### Q5｜內容 × 機制 × 技術
「哪個作品最能代表你不是只把題目放進遊戲，而是真正把內容和機制結合？」

追問：
- 如果把學習內容拿掉，遊戲還會不會一樣？
- 技術在這裡改變了什麼？

### Q6｜玩家／學習者
「哪一次你因為真實玩家行為，而不是自己的想法，改變了設計？」

追問：
- 玩家做了什麼？
- 你原本預測什麼？
- 修正後有再測嗎？

### Q7｜資料與證據
「Firebase、觀察、訪談、AI 建議，哪一種資料最容易被誤解？為什麼？」

### Q8｜整合判斷
「如果下一次重做這門課的專題，你會比現在更早問哪三個問題？」

# Part K｜學生學習單 4：Final Reflection

請個人完成，建議 300–500 字。

請包含四個元素：

1. **Earlier belief**：早期你對數位教具／AI／Web AR 的一個看法。
2. **Turning evidence**：哪一筆具體 evidence 改變你。
3. **Current judgment**：現在你如何判斷內容、學習者、媒介與 AI 的關係。
4. **Uncertainty**：哪一件事目前仍不能下結論。

### 建議起句
> 在課程前期，我較常先思考 ______。到了 ______ Evidence ID，我第一次發現 ______。之後我開始在設計前同時考慮 ______、______ 與 ______。現在我認為技術只有在 ______ 時才有價值，而 AI 比較適合 ______，不應直接決定 ______。目前最能支持這個改變的 evidence 是 ______；但對於 ______，我仍需要更多資料。

# Part L｜W18 完成度 Rubric（100 分）

> W18 評量的是「研究資料完成、證據式反思與正確解讀」，不是 TPACK 高低。

| 構面 | 權重 | Level 4 | Level 3 | Level 2 | Level 1 |
|---|---:|---|---|---|---|
| T2 / Evidence Pack 完整性 | 15 | T2 與 evidence index 完整、缺漏有清楚註記 | 大致完整 | 有多處缺漏 | 無法回查 |
| Turning Points | 20 | 三個 turning points 均呈現 belief→evidence→judgment | 多數具體 | 偏事件描述 | 無 evidence |
| TPACK Connection Reflection | 15 | 能以具體 evidence 說明知識連結，並區分工具操作 | 有合理連結 | 自標多、理由少 | 把代碼當分數 |
| ENA Interpretation | 20 | 正確解讀共現、task opportunity、限制與不確定性 | 大致正確 | 有過度推論 | 把網絡當能力排名 |
| Multi-source Triangulation | 15 | 能比較不同資料並處理不一致 | 有兩種以上資料 | 只做單一資料結論 | 混合不同資料意義 |
| Final Reflection / Interview | 15 | 能以具體 episode 說明設計判斷與限制 | 回答具體 | 偏一般心得 | 只說學到很多 |

### 評分提醒
- T2 分數本身不列入本 Rubric 高低判定。
- ENA 線多寡不影響成績。
- 誠實指出 evidence 缺漏或不確定性，不應被扣「能力」分。
- 研究者 coding 與學生自評應分開保存。

# Part P｜正式 ENA 前的資料清理檢查

## 1. Unit 是否一致？
建議 unit：`student_id`

## 2. Semantic unit / stanza 是否一致？
可選：
- `student_id + week`
- `student_id + design_episode`
- W3 early / W10–W14 integration / W15–W18 reflection episodes

選定後不要因結果不好看臨時更換。

## 3. Missingness 是否正確？
- `NA`：當時沒有觀察機會／尚未入課
- `0`：有觀察機會，但該 code 未出現

## 4. Codebook version 是否固定？
保留：
```text
coding_version = TPACK_Evidence_v1.0
```
若後續正式建立 v1.1，要記錄重新 coding 規則，不要直接覆寫歷史版本。

## 5. 是否把非 code 資料錯放進 ENA？
不要直接把以下資料當 node：
- Rubric 總分
- TPACK survey 分數
- AI 使用次數
- Firebase click 數
- 完成時間
- 玩家滿意度

# Part Q｜ENA 比較架構建議

可依研究問題選擇，不必全部做。

## 架構 A｜Early vs Late
- Early：W3–W4 或第一個可比較 design episode
- Late：W15–W18

問題：
> knowledge connections 是否從 tool-centric evidence 轉向跨內容、學習者與媒介的整合？

## 架構 B｜Before vs After Web AR
- Before：W3–W9
- Web AR：W10–W14

問題：
> 新媒介加入後，是否增加 media_translation、digital_friction、design_tradeoff 與 TCK/TPK 的共現？

## 架構 C｜AI Judgment Development
- Early AI：W3–W4
- Later AI：W13–W15

問題：

# Part S｜焦點訪談編碼備忘

訪談資料可支援：
- 補充「為什麼」；
- 解釋 event / artifact 無法說明的判斷；
- 尋找 turning points；
- 解釋 survey 與行為 evidence 不一致。

但不要把訪談當成：
- 對所有缺失資料的補寫；
- 學生事後說「我當時有想到」就直接改寫歷史 coding；
- 對課程成效的唯一證據。

若學生在 W18 提出過去從未出現在任何 contemporaneous evidence 的想法，建議標記為：

`retrospective_reflection`

而不是回填成早期 evidence。

# Part V｜課程與研究的最終界線

本課程可以支持的結論是：
- 學生在不同週次留下哪些設計 reasoning evidence；
- 不同知識與 reasoning codes 如何在 evidence 中共現；
- 學生如何描述自己的設計轉折；
- Prototype、玩家行為、AI judgment、survey 與 ENA 之間有哪些一致或不一致。

本課程單靠一學期資料**不能自動證明**：
- 某個學生具有固定的「高／低 TPACK」人格類型；
- ENA 網絡差異完全由教學造成；
- AI 或 Web AR 單獨造成學習成效提升；
- 作品分數等同 TPACK 發展；
- 自陳量表變化等同真實行為能力變化。

W18 的最終學習目標，是讓學生與研究者都能做到同一件事：

> **以可回查的 evidence 說明設計歷程，同時對資料不能支持的地方保持清楚的界線。**
