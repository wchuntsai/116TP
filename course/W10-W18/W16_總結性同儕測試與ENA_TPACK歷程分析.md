# Part A｜教師教案

## 一、W16 在整體課程中的位置

W10–W15 已完成：

**Need → Web AR Necessity → MVP → Evidence-driven Revision → AI Content Verification → Phygital Integration → AI–Human Judgment**

W16 不再教新工具，而是進行兩種總結性工作：

1. **Summative Peer Test**：用完整任務驗證目前的 Prototype。
2. **TPACK–ENA Reflection**：用自己的 evidence 回看「哪些知識開始連在一起」。

### W16 與 W18 的差異

| 週次 | 主要目的 | 學生看到／完成 | 研究端 |
|---|---|---|---|
| W16 | 課堂總結性測試與形成性歷程解讀 | Final Evidence Summary、Connection Reflection、初步 ENA／Matrix | 可用已完成的 provisional coding |
| W17 | 期末公開發表 | Prototype＋Evidence Story | 蒐集展演證據 |

# Part B｜總結性同儕測試：測「完整任務」而不是展示功能

## 測試原則

1. 從實體任務開始，不直接讓玩家看 AR。
2. 設計組只能提供正式版本中存在的規則與提示。
3. 玩家必須走完 Trigger → Digital Extension → Interaction → Return → Physical Action。
4. 觀察「做了什麼」，再詢問「為什麼」。
5. 不以「喜不喜歡」作為主要成功指標。
6. 不因技術故障直接判定作品失敗；記錄是否有 fallback。
7. 若已使用 event log，event 僅作輔助證據，不取代行為與訪談。

# Part J｜如果教師提供 ENA 圖：怎麼讀？

## ENA 圖不是雷達圖，也不是分數圖

閱讀順序：

1. **先看 node**：哪些 codes 出現在這段資料中？
2. **再看 edge**：哪些 codes 常在同一個 semantic unit 中一起出現？
3. **比較結構**：早期與後期有哪些連結增加、減少或轉移？
4. **回到原始 evidence**：圖上的線一定要能回查文字／作品證據。
5. **檢查 opportunity**：某 code 少，是否只是該週任務沒有提供觀察機會？

### 不可以這樣說
- 「我的 TPACK 分數變高了。」
- 「線比較多，所以我比較厲害。」
- 「我的網絡比別組好。」
- 「沒有某條線代表我沒有這個能力。」

### 可以這樣說
> 在 W3 的 evidence 中，我的技術描述主要集中在 TK 與 TPK；到 W13–W15，我開始出現 AI_human_judgment、content_alignment 與 TCK/TPK 同一 evidence unit 的連結。這表示我留下的設計推理證據開始包含較多跨面向判斷。但是否代表能力提升，還需要結合任務差異與其他資料解讀。
